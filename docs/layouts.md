# Building an office from a drawing

An office is compiled from a layout description — a JSON file that says what a
floor plan says. Nothing in it is a raw tile number, and nothing in it is
guessed: furniture is named from an index generated by measuring the art itself.

    node apps/web/scripts/build-office.mjs apps/web/layouts/head-office.json

## Why it exists

The first office was hardcoded: six tiles picked by eye out of 27,232, with
furniture positions written as atlas indices. Three separate times a single
decorative plant sealed a doorway — invisible in the map file, discovered only
by walking into it. The collision body sits half a tile below the sprite, so a
plant that looks clear on paper blocks the corridor in practice.

So the compiler refuses to write a map it cannot prove is walkable, and it
names the room that got sealed.

## The description

```json
{
  "width": 30,
  "height": 20,
  "palette": { "carpet": 2468, "teal": 1776, "wall": 4996 },
  "floor": "carpet",
  "wall": "wall",
  "entrance": { "x": 15, "y": 17 },
  "rooms": [
    {
      "name": "Standup",
      "kind": "meeting",
      "x": 2,
      "y": 2,
      "w": 10,
      "h": 8,
      "floor": "teal",
      "doors": [{ "x": 6, "y": 9, "w": 2 }],
      "furniture": [{ "object": "conference-hall#11", "x": 2, "y": 2 }]
    }
  ]
}
```

| Field               | Meaning                                                                                                              |
| ------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `palette`           | Names for the tiles this office uses. A description never carries a bare number.                                     |
| `rooms[].kind`      | `meeting`, `booth`, `desk` or `quiet`. A room with a kind becomes a private-audio zone; `"private": false` opts out. |
| `rooms[].doors`     | Openings left out of the wall, in **absolute** coordinates. Without one the room is sealed and the build fails.      |
| `rooms[].furniture` | Positions are **relative to the room**, so moving a room moves its contents.                                         |
| `furniture`         | Loose pieces in absolute coordinates — a plant in a corridor, a reception desk on the open floor.                    |
| `object`            | `sheet#index` into `apps/web/public/assets/limezu/objects.json`.                                                     |

## Finding an object

The index is generated, not written by hand:

```
node apps/web/scripts/generate-objects.mjs
```

It flood-fills each sheet's alpha channel, so every object's footprint is
measured rather than eyeballed — a sofa that looks three tiles wide is 2.6
tiles of pixels and needs three. 3,751 objects across 26 sheets.

To see what an index refers to, render the sheet with its boxes labelled:

```
python3 apps/web/scripts/label-objects.py \
  apps/web/public/assets/limezu/tiles/conference-hall.png \
  objects-raw.json conference-hall out.png 3
```

The same objects are in the admin panel under **Objects**, where you click a
picture instead of looking up a number.

## What the compiler refuses

Both checks come from `findLayoutProblems` in the shared package, which the
server runs again on publish — a layout that passes here cannot be rejected
there, and a layout that fails here never reaches anyone.

- A room with no route from the entrance — _"Standup cannot be reached from the
  entrance"_.
- A room reachable but furnished down to a single tile — a doorway with a name,
  not a room.
- An entrance placed inside a wall.

Every sealed room is reported at once. Fixing a layout one error per run is
miserable when a single misplaced wall has cut off four of them.
